# База данных winvino

Postgres 18.6. Зеркало каталога [vino-svoe.ru](https://vino-svoe.ru/wines) плюс таблицы
под сканер этикеток.

## Инвариант

Схема и данные меняются **только закоммиченным файлом-миграцией**. Ни руками в клиенте,
ни разовым скриптом. Применение:

```
npm run db:migrate     # применить недостающие
npm run db:status       # показать, что ожидает применения
npm run catalog:sync    # пересинхронизировать каталог из API (идемпотентно)
```

Применённые миграции и их sha256 лежат в `public.schema_migrations`. Раннер откажется
работать, если файл уже применённой миграции изменился — правка делается новой миграцией.

## Имена миграций

```
<timestamp UTC>_<TASK>_<feature>_<action>.sql
```

Префиксы `feature` этого проекта (список экосистемы Zerocoder здесь не применяется):

| Префикс | Модуль |
|---|---|
| `system_` | Расширения, общие функции, триггеры |
| `catalog_` | Зеркало каталога: вина, винодельни, справочники |
| `scanner_` | Сканер этикеток: сканы, OCR, метрики матчера |

## Расширения

Включены в схему `extensions` (не в `public`, чтобы не мешать дампам):
`pg_trgm`, `unaccent`, `fuzzystrmatch`. `search_path` выставлен **на базу**, а не на роль —
роль `postgres` общая для всех 17 баз кластера, `ALTER ROLE` протёк бы в остальные.

**`pgvector` не установлен на сервере.** `pg_available_extensions` его не содержит,
поставить из строки подключения нельзя — нужен root на хосте (`apt install
postgresql-18-pgvector` либо образ `pgvector/pgvector:pg18`). До тех пор эмбеддинги в
`wine_photos` лежат как `real[]`. Переход, когда пакет появится:

```sql
ALTER TABLE wine_photos
  ALTER COLUMN embedding_full  TYPE extensions.vector(512) USING embedding_full::extensions.vector(512),
  ALTER COLUMN embedding_label TYPE extensions.vector(512) USING embedding_label::extensions.vector(512);
```

Индексы (HNSW/IVFFlat) при 2041 строке не нужны: полный перебор дешевле накладных расходов.

## Матчер: как устроен поиск

Название вина **не идентификатор** — «Рислинг» это 37 разных вин. Первичный сигнал —
винодельня, поэтому поиск двухступенчатый:

1. **Ступень A** — OCR-строка → винодельня. Триграммы по `manufacturers.name_norm` и
   `slug_norm`, то есть кириллица и латиница одновременно. Сужает 2041 → в среднем 15.
2. **Ступень B** — вино внутри портфеля. Медиана 8 вин на винодельню, но распределение
   перекошено: `Фанагория` 101, `Кубань-Вино` 97, `Мысхако` 92.
3. **Ступень C** — `wine_color` и `sweetness` разводят остаток (69 коллизий вида
   «производитель + название»); оба слова напечатаны на этикетке.

`public.norm_label()` канонизирует текст: регистр, `ё→е`, удаление `ъ`/`ь`
(«Ведерниковъ» → `ведерников`), пунктуация в пробелы. Латиница сохраняется.

## Особенности источника, на которые натыкались

- **`perPage` максимум 30.** 31 и больше — HTTP 400. Полный каталог = 69 запросов.
- **`publicRating` дробный.** В списке выглядит целым (`2`, `4`), в деталях приходит
  `2.25`. Поэтому `numeric(3,2)`, а не `smallint`.
- **Поле `color` в API — не цвет вина,** а описание оттенка («Соломенный с золотистыми
  переливами»). В схеме называется `hue`. Цвет вина берётся из `category`.
- **Год урожая есть только у 112 названий из 2041.** Как фильтр непригоден, только
  слабый тайбрейкер. Отдельного поля в API нет вовсе.
- **У 3 виноделен API не отдаёт слаг.** `Поместье Голубицкое`, `Mancopia`,
  `Wein und Wasser` приходят в `/wines/{slug}` как `{name}` без `slug`, и в
  `/manufacturers` отсутствуют. Слаг для них генерируется локально (`slugify()` в
  `scripts/sync-catalog.mjs`), иначе их 9 вин остаются без винодельни.
- **`Поместье Голубицкое` и `Golubitskoe Estate` — вероятно одна винодельня** под двумя
  названиями. В базе это две строки. Merge алиасов — отдельная задача.
- **`altText` у картинок ненадёжен:** расходится с `title` у 987 вин из 2041, местами
  просто неверен. Как источник названия не использовать.
- **Прямой путь к картинке отдаёт 404.** Только через ресайзер:
  `https://api.vino-svoe.ru/v1/img/str-api/{w}/{h}/resize/uploads/xxx.webp`.

## Eval-набор

`label_scans` — измерительный прибор матчера: фото, OCR, эталонный slug, предсказание,
`truth_rank` (1 = top-1, NULL = не попал в выдачу) и `candidates` с топом кандидатов.
`truth_absent = true` означает «вина нет в каталоге» — такие кадры обязательны, иначе
метрика не увидит уверенного вранья на импортном вине.

Сводка: `SELECT * FROM label_scan_accuracy;` — top-1, top-5 и false positives по версиям
матчера, только по `source = 'eval_set'`.
